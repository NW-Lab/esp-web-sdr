# ESP-WebSDR をローカル・オフラインで起動する方法

このフォークは、閲覧アプリ、ブラウザ用フラッシャー、対応する `firmware/` イメージをすべてリポジトリー内に保持しています。クローン後はインターネット接続なしで起動・閲覧・ブラウザ上のファームウェア書き込みができます。

## 起動

`file:///.../index.html` を直接開かず、必ず `localhost` のローカルサーバー経由で開いてください。Web Serial を使うにはブラウザの安全なローカルコンテキストが必要です。

| OS | 起動方法 |
|---|---|
| Windows | `start-windows.bat` を実行 |
| macOS / Linux | `chmod +x start-linux-macos.sh` の後に `./start-linux-macos.sh` を実行 |

Python 3 が必要ですが、追加の Python パッケージは不要です。起動後、デスクトップ版 Chrome / Edge / Brave で **<http://localhost:8765/>** を開いてください。停止は実行したターミナルで `Ctrl+C` です。

同梱サーバーは `127.0.0.1` のみに待ち受けるため、LANへ公開しません。起動時とファームウェア書き込み時のファイル取得はこのリポジトリー内で完結します。画面内の外部リンクはクリックした場合だけ外部サイトを開きます。

## Wi-Fi CH 表示

スペクトラム下部の測定バーには **Wi-Fi CH** が表示されます。

- 中心周波数が標準Wi-Fiチャンネルと一致するときは、例として `CH 1 · 2.4 GHz` のように表示
- 一致しないときは、受信スパン内の標準チャンネルを要約表示
- 2.4 GHz（CH 1–14）、主要5 GHz帯（CH 36–177）、6 GHz帯（CH 1–233）を対象

これは周波数の対応表であり、ボードの対応範囲、地域ごとの利用可否、電波法上の利用可否を保証するものではありません。

## ブラウザフラッシャー

ファームウェアを書き込む場合は、ローカルサーバー起動後に **<http://localhost:8765/flash.html>** を開きます。実際のチップ・フラッシュ容量に合うプロファイルを選択してください。

> **注意:** 書き込みはボード上の既存ファームウェアとパーティションテーブルを置き換えます。誤ったチップのプロファイルを選ばないでください。

ESPtool を用いる場合は、各 `firmware/<profile>/flash_command.txt` と `flash_args` をオフラインで参照できます。使用するポートとチップに合わせてコマンドを確認してから実行してください。

## 検証

```sh
node --test tests/*.test.mjs
```

テストには、Wi-Fi CH の周波数対応と既存の無線・フラッシャー挙動の回帰確認が含まれます。
